# 一、QuantRadar 基于 BulletTrade 代码基线

QuantRadar 不是从零开始，而是以 BulletTrade 为代码基线继续开发。

```text
bullet-trade (upstream)
        ↓ git clone
QuantRadar (origin, 当前开发仓库)
```

```text
禁止：将 BulletTrade 作为 PyPI 依赖与源码版并存
禁止：创建 vendor/bullet-trade 嵌套 Git 仓库
禁止：重写 BulletTrade 核心（见 00 第四节 / 04 第一节）
```

# 二、Git 规范

```text
upstream = BulletTrade 原始仓库（只读跟踪，用于同步上游）
origin   = QuantRadar 开发仓库（日常提交）
```

操作：

```bash
git remote rename origin upstream   # 仅在 clone 后初始化时
git remote add origin <quantradar-repo>  # 如有自有远端
```

提交纪律：

```text
每次 ACTIVE_PHASE 完成 → 一个清晰 commit
commit message 说明「做了什么 + 验收标志」
不要在一个 commit 里混入无关 Phase 的工作
不要自动进入下一 Phase 后继续提交
```

禁止：

```text
禁止向 upstream 推送本地修改
禁止在主线 commit 里夹带实验性 / 未测试代码
```

# 三、Python 环境与 .venv

```text
Python 版本：3.11
虚拟环境：QuantRadar/.venv（项目内，随仓库 .gitignore）
安装方式：pip install -e .（可编辑，指向当前源码）
```

验证：

```python
import bullet_trade
print(bullet_trade.__file__)   # 必须指向 QuantRadar 当前源码
```

禁止：

```text
禁止在系统 Python 直接安装
禁止同时安装 PyPI bullet-trade 与源码版
禁止在 .venv 之外运行测试
```

Node（仅 Web 阶段需要）：

```text
Node 版本见 BASELINE.md（当前阶段若不开发 Web，可不记录）
```

# 四、项目目录结构

约定（以实际代码为准，CURRENT_STATE 记录偏差）：

```text
QuantRadar/
├── .venv/                 # Python 环境（不入库）
├── docs/                  # 本文档体系
├── src/bullet_trade/      # BulletTrade 核心（fork 基线，谨慎修改）
├── src/quantradar/        # QuantRadar 扩展（Provider / 服务 / Web / Qlib 桥接）
├── tests/                 # 测试
├── runs/                  # 回测运行输出（见 04 Run 目录）
├── pyproject.toml         # 依赖与构建配置
└── README.md
```

新增顶层目录前，先确认属于哪个 Phase，并在 CURRENT_STATE 记录。

# 六、日志规范

```text
统一使用 Python logging，不混用 print 做关键日志
日志分级：DEBUG / INFO / WARNING / ERROR
禁止：用日志吞掉异常（不要用 logging 替代错误处理）
数据缺失 / BLOCKED 必须显式 WARNING 或 ERROR，不能静默
```

---

# 七、测试目录与单文件限制

```text
测试位置：tests/（按模块分子目录，如 tests/provider/）
测试框架：pytest
每个测试可独立运行，不依赖外部未声明状态
```

单文件限制：

```text
单个源文件不超过 ~400 行（超出应拆分模块）
单个测试文件聚焦一个能力
禁止：把多个不相关能力塞进一个巨型文件
```

---

# 八、数据存储基础设施

```text
Parquet：本地中间数据 / 因子 / signal 落盘（见 03 / 06）
PostgreSQL：仅服务化阶段（Phase 7）的 Strategy / Run / Experiment 元数据
```

```text
禁止：在研究主线早期引入 PostgreSQL 作为数据事实源
投资_data 才是事实源（见 03），PostgreSQL 只是工作流元数据
```
