# 一、QuantRadar 基于 BulletTrade 代码基线

QuantRadar 不是从零开始，而是以 BulletTrade 为代码基线继续开发。

```text
BulletTrade 原始仓库（github.com/BulletTrade/bullet-trade）
        ↓ git clone 后剥离 .git，作为受控快照
vendor/bullet-trade/            # BulletTrade v0.9.2 快照（无嵌套 Git）
QuantRadar 根目录                # 自有 Git 仓库（.git 在根）
```

QuantRadar 根目录是**项目自己的仓库**，`vendor/bullet-trade/` 只是 BulletTrade 的受控代码快照（记录 upstream URL + base commit 于 `BASELINE.md`），不保留完整 Git 历史，也不建立 upstream remote。

```text
禁止：将 BulletTrade 作为 PyPI 依赖与源码版并存
禁止：在 vendor/bullet-trade/ 内保留 .git（禁止嵌套 Git 仓库）
禁止：向 BulletTrade upstream 推送任何修改
禁止：重写 BulletTrade 核心（见 00 第四节 / 04 第一节）
```

# 二、Git 规范

```text
QuantRadar 根目录 = 唯一 Git 仓库（origin = KenGGG/QuantRadar）
vendor/bullet-trade = 受控快照，不建立 remote，也不保留 .git
BulletTrade upstream 信息（URL + base commit）仅记录于 BASELINE.md，不配置为 git remote
```

> 注意：本仓库**不**配置 `upstream` remote。同步上游变更时，手工 diff / patch 到 `vendor/bullet-trade/`，并在 `BASELINE.md` 更新 base commit，而不是 `git remote add upstream` 后 merge。

提交纪律：

```text
每次 ACTIVE_PHASE 完成 → 一个清晰 commit
commit message 说明「做了什么 + 验收标志」
不要在一个 commit 里混入无关 Phase 的工作
不要自动进入下一 Phase 后继续提交
```

禁止：

```text
禁止向 upstream 推送本地修改
禁止在主线 commit 里夹带实验性 / 未测试代码
```

# 三、Python 环境与 .venv

```text
Python 版本：>=3.11,<3.13（本机验证 3.12.3；3.11 与 3.12 均支持，3.13 未验证/不支持）
虚拟环境：QuantRadar/.venv（项目内，随仓库 .gitignore）
安装方式：pip install -e ./vendor/bullet-trade（可编辑，指向 vendored 当前源码）
```

验证：

```python
import bullet_trade
print(bullet_trade.__file__)   # 必须指向 QuantRadar/vendor/bullet-trade/bullet_trade/__init__.py
```

禁止：

```text
禁止在系统 Python 直接安装
禁止同时安装 PyPI bullet-trade 与源码版
禁止在 .venv 之外运行测试
```

Node（仅 Web 阶段需要）：

```text
Node 版本见 BASELINE.md（当前阶段若不开发 Web，可不记录）
```

# 四、项目目录结构

约定（以实际代码为准，CURRENT_STATE 记录偏差）：

```text
QuantRadar/
├── .venv/                       # Python 环境（不入库）
├── vendor/bullet-trade/         # BulletTrade v0.9.2 受控快照（无 .git；bullet_trade/ 为核心包）
├── docs/                        # 本文档体系（控制文档 + 规范）
├── backend/                     # QuantRadar 服务端扩展（FastAPI / Worker，Phase 7 起）
├── frontend/                    # WebUI（React/TS，Phase 7/8 起）
├── strategies/                  # 策略脚本（独立于 BulletTrade 核心）
├── tests/                       # 测试（含 vendor/bullet-trade/tests 内的基线测试）
├── runs/                        # 回测运行输出（见 04 Run 目录）
├── pyproject.toml               # 依赖与构建配置
├── requirements.lock            # 锁定依赖
└── .gitignore
```

说明：

```text
BulletTrade 核心永远位于 vendor/bullet-trade/bullet_trade/，作为受控快照谨慎修改
QuantRadar 扩展（Provider / 服务 / Web / Qlib 桥接）落在项目根级包（backend/、strategies/ 等），不放进 src/
外部 Provider 通过 Generic Provider Registry（见 03）注册，无需修改 vendor 内 _create_provider 的硬编码分支
新增顶层目录前，先确认属于哪个 Phase，并在 CURRENT_STATE 记录
```

# 六、日志规范

```text
统一使用 Python logging，不混用 print 做关键日志
日志分级：DEBUG / INFO / WARNING / ERROR
禁止：用日志吞掉异常（不要用 logging 替代错误处理）
数据缺失 / BLOCKED 必须显式 WARNING 或 ERROR，不能静默
```

# 七、测试目录与单文件限制

```text
测试位置：tests/（按模块分子目录，如 tests/provider/）
测试框架：pytest
每个测试可独立运行，不依赖外部未声明状态
```

单文件限制：

```text
单个源文件不超过 ~400 行（超出应拆分模块）
单个测试文件聚焦一个能力
禁止：把多个不相关能力塞进一个巨型文件
```
