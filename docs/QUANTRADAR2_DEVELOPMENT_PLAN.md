## 1. 授权、目标和完成边界

用户已要求将本文件设为后续 Codex 开发目标，并持续推进开发；明确允许引入 SQLite，QuantRadar2 暂不开发交易能力。本轮持续执行里程碑为 **G0 → G1 → G2：首版研究工作台交付**。G3 为后续研究扩展路线，首版完成后汇报，不自行选择新策略或无限扩展接口。

产品定位：Windows 11 本地、单用户、可信策略的聚宽风格研究 WebUI；BulletTrade 是唯一回测引擎，大 QMT 是唯一外部数据来源。网页完成策略编辑、保存、参数配置、模拟回测、日志查看、历史记录及原生报告浏览。

成功标准：日频和分钟回测可用；相同输入下网页与直接运行 BulletTrade 的成交、持仓、权益与指标一致；任务可停止、失败可定位、重启可恢复记录；无需启动旧双 Dolt、PostgreSQL、DataHub、Qlib、Kronos 或研报采集。

### 不可突破的边界

- 不修改大 QMT 程序、内置环境、包、策略或配置；GUI 操作由用户手动完成。
- 已允许 QMT 自身正常行情下载、缓存刷新；这不代表允许修改安装文件或策略。
- 不调用真实下单、撤单、规则撤单、批量撤单或资金操作；不以真实请求验证交易拒绝。
- QuantRadar2 不提供交易入口、实盘运行、交易凭证管理或任意 RPC 转发；模拟回测订单仍由引擎正常处理。
- 不修改 BulletTrade 回测引擎，不把研究 RPC 替换为行情自动备用源。
- 不新增 QMT 以外的数据来源；SQLite 仅存应用元数据，不建设通用行情数据库。
- 保留 V1 文件、历史数据库和研究产物；不批量删除旧目录，不迁移整个旧数据库。
- 不推送旧仓库 main，不自动合并、部署或发布；本地开发使用独立分支。
- 普通测试失败、依赖适配和可逆修复不要求再次确认；缺权限、外部条件或越界变更时记录具体阻塞并请求所需最小授权。

## 3. 架构与旧系统迁移

### 主链路

WebUI → 精简 FastAPI → SQLite任务元数据 → 独立回测子进程 → BulletTrade原生引擎 → 数据专用qmt-remote服务 → 已有大QMT Gateway → QMT。

后续研究补充：QMT研究RPC → 独立研究适配层 → 数据预览/已验收研究扩展。首版不将财务/历史成分冒充完整聚宽get_fundamentals及严格历史股票池。

### 实现布局与复用原则

- 新后端包使用 `backend/quantradar2`，新入口 `scripts/v2_api.py`（调用 `quantradar2.api.create_app`）；禁止导入V1 bootstrap、InvestmentDataProvider、DataHub维护锁及数据库初始化。保留V1后端供参考和回退。
- 复用frontend现有React/TypeScript、Ant Design、Monaco、ECharts及三个核心组件的布局；建立V2入口和API模块，迁移时剪除真实依赖，不仅隐藏菜单。V1前端入口保留可单独构建。
- V2只展示策略工作台、回测记录/报告、数据与连接三个入口；日频/分钟标识来自实际配置。设置放附属面板，不迁入ETF专页、实验组、FactorLab、Qlib、Kronos、研报。
- `requirements-v2.txt` 提供V2最小依赖路径，V2安装不能强制安装旧机器学习/数据采集依赖；BulletTrade来源路径与锁定版本显式记录，启动检查实际加载路径，禁止静默加载旧vendor。
- Windows启动/停止脚本均位于仓库，服务绑定127.0.0.1；采用V2独立端口，默认Web API 7242，数据服务58621；占用时启动报错，用户可配置，不自动停止已有进程。
- V2使用独立虚拟环境，基于已验收Python版本；不改现有BulletTrade或QMT环境。新环境安装记录依赖锁和BulletTrade实际源码身份。

## 4. SQLite、产物和公共接口

SQLite使用Python标准库sqlite3，文件位于可配置V2运行目录，默认 `var/quantradar2/metadata.sqlite3`；不提交真实数据库、凭证、运行日志或报告产物。

最小实体：schema版本、策略及不可变修订、回测任务、产物索引。任务保存策略修订、提交参数、最终生效设置、引擎/运行器身份、状态、时间、退出码、错误和运行目录。凭证留在本地环境配置，不进SQLite或报告。

采用事务、外键、WAL及busy_timeout；schema变更以版本迁移执行，不删除已有任务。API是任务元数据的唯一写入者，子进程只写自己的产物；历史任务重开创建新任务，不覆盖旧运行。

每次任务独立目录保存strategy.py、request.json、effective_config.json、environment.json、backtest.log、原生HTML/CSV/指标和产物清单。所有artifact访问按已登记run_id和相对路径解析，禁止请求任意文件路径。失败也保留源码、参数和日志。

公共接口统一 `/api/v2`：

- health：Web服务状态、实际引擎身份、数据链路资格；数据不可用不阻止查看历史报告。
- strategies：列表、创建、读取、保存新修订、复制；空白源码及非法参数明确报错，不自动替换成买入持有。
- runs：创建任务（返回run_id）、列表、详情、停止、增量日志、已登记产物和原生报告数据。
- data：连接诊断、显式代码资料、有限窗口行情预览及能力目录；没有任意RPC代理接口。

运行配置只开放源码、开始/结束日期、日频/分钟、初始资金、基准和策略参数。费用、滑点等首版由策略的BulletTrade原生API设置，网页不提供冲突覆盖；引擎可公开取得的生效值记录到effective_config，未能取得的值标记unknown而不伪造。固定标的参数区分交易对象和指数基准，不把指数当股票交易。

## 5. 执行器与数据边界

- 首版并发为1，任务先进先出，状态QUEUED → RUNNING → SUCCEEDED/FAILED/CANCELLED/INTERRUPTED；停止排队任务直接CANCELLED，运行任务终止自己的进程树，不操作QMT或共享数据服务。
- 用户代码是本人编写或审查的可信代码，子进程隔离全局设置并不等于安全沙箱。启动参数显式backtest，不调用live模式，不载入远程券商配置。
- 执行器设置可配置超时（默认30分钟）；日志持续输出，非零退出码及缺报告产物均FAILED。API重启后检查运行器PID和身份：仍存在则核验身份后终止本应用遗留进程；按有效完成清单恢复，否则标记INTERRUPTED，不重新执行原任务；不可按单个PID杀未知进程。
- 服务端Broker禁用：本机BulletTrade支持 `--disable-broker`，为V2单独启动数据专用服务、独立端口和令牌，服务与配置均在QMT安装目录外。策略子进程不继承现有broker服务令牌和Gateway内部密码。
- 用静态路径审查和离线替身测试证明broker请求在服务端进入适配器前拒绝；不向真实QMT发送测试交易请求。真实health只验证features=data及禁用状态，不能以ready作为只读证明。
- 已有Gateway仍开放交易须如实列示。V2的隔离是可信本地研究流程的应用层隔离，不承诺恶意Python无法自行访问本机。若用户要求Gateway自身只读，属于需单独授权的配置变更，不能自行修改。
- 数据能力目录分别记录接口可调用、样本覆盖、历史视角、单位和限制。页面按所选策略/窗口显示完整、有限或不可用；关键数据缺失拒绝运行，非关键限制展示原因。
- QMT字段/时间转换集中在对应适配层；第一版遵循BulletTrade已有量价口径，未验收证券全列表不作为默认股票池。

### G2：首版正式交付

1. 固定买入持有、日频双均线、固定ETF池月度动量、分钟回调/交易策略场景；池及区间按实际覆盖确定并写入验收夹具，不伪造缺数据。
2. 验证预热、竞价/首分钟、午休、收盘、费用、生效参数、停止/超时/重启与报告一致性。
3. 建立有限输入冻结包：在Provider边界记录验收任务实际返回的行情、日历、证券资料和引擎实际使用的事件/因子。保存返回内容、请求键、取得时间、来源与hash，不只保存日期和hash。
4. 冻结回放使用独立只读Provider，禁止回源，缺请求键失败；不改引擎、不恢复DataHub、不承诺支持所有策略。对日期/复权参考时点等非数据输入也固定记录，无法固定的场景明确不支持回放。
5. 同一冻结包下直接运行与网页任务的成交、持仓、权益、指标一致；不同普通QMT读取不宣称永久可复现。
6. 完成Windows安装/启动/停止、可信策略与数据限制文档；通过后里程碑完成并向用户汇报。

## 7. 验证策略

- 元数据：策略修订不可变、事务一致性、任务排队及合法状态迁移、schema升级保留数据、停止与重启恢复。
- 隔离：V2启动不导入旧DataHub/数据库；禁broker服务在替身环境拒绝交易且适配器调用次数为0；运行器仅以backtest模式启动，日志和产物不泄露凭证。
- 数据：现有六组证据保留，新增测试针对实际迁移产生的风险；关键缺口、全NaN、异常值、当前数据冒充历史均明确失败。
- 回测：以同一冻结输入包建立API/直接运行差分，逐项比较原生成交、持仓、权益和指标；金额误差阈值必须有明确单位理由，不掩盖竞价/复权差异。
- 前端：npm.cmd typecheck/build；工作台保存/运行/停止/错误、日志及报告重开浏览器验收；不为纯文案/静态改动增加镜像测试。
- 所有真实测试不调用交易接口；完成所需定向测试后，不无理由重复全量检查。
