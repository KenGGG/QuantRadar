# 产品边界与核心原则

文件：`docs/01_产品边界与核心原则.md`

本文件定义 QuantRadar「是什么」与「不是什么」。

本文件是稳定产品规则，不含代码细节。架构、接口、数据结构见 `02`～`06`。

---

# 一、产品是什么

QuantRadar 是一个**本地优先**的 A 股量化研究平台，用于在 Ubuntu 上完成：

```text
可信数据接入
→ 统一数据 Provider
→ BulletTrade 可靠回测
→ Snapshot 与可复现实验
→ 中文 Web 工作台
→ Qlib 高级因子研究
```

它的价值是「一条可信研究主线」，不是功能堆叠。

---

# 二、产品不是什么

以下明确不属于当前 QuantRadar 主线范围：

```text
不是实盘交易系统（QMT / 券商下单 / 实盘执行）
不是 Windows 桌面应用（Windows 仅属于未来实盘节点）
不是新的回测引擎（撮合、组合、订单由 BulletTrade 负责）
不是新的因子库框架（Qlib 已提供）
不是数据生产方（数据来自 investment_data，不自己造数据）
不是通用投研社区 / SaaS 平台
```

任何被上述列表排除的能力，未经 `ACTIVE_PHASE.md` 明确授权，不得开发。

---

# 三、平台边界：Ubuntu 与 Windows

当前主平台：

```text
Ubuntu —— 研究、回测、数据、Web、Qlib 全部在此运行
```

边界规则：

```text
Ubuntu 主线能力：全部研究功能
Windows 能力：仅未来实盘执行节点（QMT）相关
```

```text
禁止：在研究主线中假设 Windows / QMT 已可用
禁止：因为实盘能力缺失，阻塞研究主线
允许：在 BASELINE / CURRENT_STATE 中如实标记「Windows/QMT 能力未在本环境验证」
```

实盘执行是独立阶段，与当前研究平台解耦。

---

# 四、A 股优先

数据与研究主线以 A 股股票为第一优先级：

```text
A 股股票 = 主线 READY 目标
```

当 A 股主线与 ETF / 其他资产发生冲突或资源竞争时，优先保障 A 股。

---

# 五、ETF 独立门禁

ETF 是一组**独立能力**，拥有自己的门禁，不得反向影响股票主线。

```text
允许：
A股股票 = READY
ETF    = BLOCKED

禁止：
ETF数据不足 → 停止整个 QuantRadar 开发
ETF能力不足 → 阻塞 A 股回测 / Web / Qlib
```

ETF 能力（价格、NAV、因子、公司行为、Total Return、规模、流动性）只在 Phase 11 被逐项建设，且不得提前占用主线。

---

# 六、不做什么（明确禁止清单）

以下行为即使在路线图中看到相关关键词，也禁止提前实施：

```text
禁止重写 BulletTrade 撮合 / 组合 / 会计
禁止自建回测引擎
禁止自动 fallback 到 JQData / Tushare / AkShare 替代 investment_data
禁止伪造成功（except 吞异常、假 adjclose、假分红）
禁止提前开发 React / WebUI / FastAPI / Worker（未到 Phase 7/8）
禁止提前开发 Qlib 模型（未到 Phase 10）
禁止提前补 ETF 数据（未到 Phase 11）
禁止提前接入 QMT / 实盘（未到未来实盘节点）
禁止自动进入下一个 Phase
```

# 七、最终用户体验（目标画像）

QuantRadar 最终应让研究者在本机完成：

```text
1. 在中文界面编写 / 加载策略
2. 一键发起 A 股日频回测
3. 查看 NAV / 持仓 / 交易 / 指标
4. 查看数据覆盖与缺失状态（明确 BLOCKED）
5. 保存每次实验的 Snapshot，可复现
6. 用 Qlib 做高级因子研究，结果回到 BulletTrade 闭环
```

判断标准：任何新增功能若不能加强上述主线，暂不实施（见 `00_开发入口.md` 第七节）。
