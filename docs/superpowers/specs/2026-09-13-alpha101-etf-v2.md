## 0. 本轮交付与不可改变的边界

沿用原任务 G0—G4，交付 Alpha101 研究输入包、一个境内权益 ETF 价格型轮动数据包，以及与二者直接相关的状态/公司行为/收益校验。不新建研究平台，不重做已验收 WebUI，不引入第三个事实库，不扩展分钟线、实盘、NotebookLM、全财务 PIT 或全基金持仓工程。

- `/data/investment_data` 是基础历史库，保持只读；只允许既有可信 remote 的干净 fast-forward。需要同步时生成新的固定版本，不能改变旧 release 的基础 commit。
- `/data/quantradar_data` 承接新增候选事实、审计及发布。回测固定两个 commit，禁止联网和运行时静默换源。
- 继续使用现有 Adapter、Governor、daily coordinator、journal、release、Provider 和 BulletTrade，不另起重复的调度与采集系统。
- 不新增 Tushare 在线采集；基础库中已有 `ts_*` 表仍可在来源与覆盖核验后复用。
- 每次只扩一个逻辑数据集或一个接口契约：小样本→候选→质量验收→回放→发布，再推进下一项。研发不同时启动所有端点的全历史任务。
- 因子“能够计算”、统计研究“可评价”、账户“可交易回测”、严格 PIT 四种资格分开。某项行业或 NAV 缺失，只阻塞真正依赖它的工作流。

### 0.1 事实依据与优先级

本地实施首先读取 `docs/ACTIVE_PHASE.md`、`docs/CURRENT_STATE.md`、DataHub V2 验收目录及实际 schema；其中 ACTIVE_PHASE 是当前目标的依据。用户提供的 CURRENT_STATE 和 R22 记录仅作为初始事实，不代替本次数据库盘点。

沿用已有基线：低 Beta 已有固定版本回放；298 只股票、11,347 条状态记录只服务指定月度依赖；196 个解析失败和 123 个覆盖未验证项保留原分母与原因。不得据此宣称逐日全市场状态完整、历史指数池完整或严格 PIT 完整。[S1]

## G0：先盘点与锁契约，再决定联网任务

### G0.1 冻结环境与接口

记录 Python、AKShare、BaoStock 安装版本，以及每个拟用函数的 `inspect.signature()`、源文件 SHA-256、适配器 commit。先运行随附 `quantradar_data_interfaces_check.py` 做离线检查；它不测试网络健康。禁止为解决一个端点问题直接对生产环境执行全局 `pip install -U`。

```bash
# 使用 QuantRadar 已有 Python 环境，不安装/升级包，不连接数据接口或数据库。
python quantradar_data_interfaces_check.py --output /tmp/quantradar_interface_contract_report.json
```

脚本拒绝覆盖同名输出；再次检查请使用新文件名。退出码 0 仅表示所列示例与本地签名兼容，退出码 2 表示有缺包、签名不匹配或需人工复核，均不能解释为接口健康/宕机。a-stock-data 没有作为可导入 SDK 检查，按固定 SKILL 代码和现有适配器另行核验。

接口状态至少分开为：

`DOCUMENTED` → `LOCAL_SIGNATURE_CHECKED` → `SMOKE_PASSED` → `SCOPED_QUALIFIED` → `RELEASED`

函数存在、参数可绑定，不等于返回列正确；样本成功，不等于全区间覆盖；同一来源不同包装，不等于独立对拍。

### G0.2 缺口分类与范围

为两个研究包生成精确的证券×日期×字段×用途清单，使用：

`REUSE / REPARSE_RAW / DERIVE / FETCH / UNKNOWN / NOT_APPLICABLE`

参考评价区间仍为 2020-01-01—2026-08-31。预热长度按每个 Alpha 的嵌套算子传播计算，并增加收益标签/执行日所需边界，不统一写死为 250 日。候选池、形成期、调仓日、执行日、持仓估值日都计入依赖；不能仅补第一次回测成交的股票。

先扫描基础表和已有 payload。现有 BaoStock daily_bundles 的已存 SDK 响应包含 OHLC、volume、amount、turn、tradestatus、isST，可优先重解析；此前未请求的 `preclose` 不能在本地凭空恢复。现有东财日期切片请求 `columns=ALL`，要检查实际响应是否已经含市值/股本，不因正式估值表没发布这些字段就重新下载。[S1]

### G0.3 请求粒度表

| 逻辑资料 | 正确的采集/缓存粒度 | 不允许的重复模式 |
|---|---|---|
| BaoStock 日线、状态 | 证券×必要连续日期段；一会话串行多证券 | 每个字段单独查询；每个交易日登录 |
| 证券基本信息 | 全列表快照或单证券补漏 | 用当前列表假装历史每日全名单 |
| ETF 日行情 | ETF×必要日期段；按实际端点请求次数审计 | 回测每读一根 K 线就联网 |
| 东财市值 | 单证券的接口全可得历史，或复用既有按日切片 | 对每个交易日重复调一次仅支持 symbol 的全历史接口 |
| 申万变迁史 | 全市场文件一次获取并缓存 | 为每只股票下载同一份文件 |
| 基金分红/拆分 | 年份×页；全基金候选获取后筛首批 ETF | 每只 ETF 再下载相同年份的全基金分页 |
| 基金公告 | 基金×公告类别×页 | 只读首页就把历史标成完整 |
| 当前指数成分 | 指数×源侧快照日期 | 把今天快照复制到所有历史日期 |

## G1：Alpha101 数据接口与字段用法

### A1. 日行情、停牌、ST：优先复用 BaoStock 已验收路径

**主接口**：`bs.query_history_k_data_plus`。扩展既有 `BaostockAdapter.daily_bundles()`，在同一响应中按字段契约派生价格候选和状态候选，各自审计发布；不能因一次取回就无条件同时发布所有字段。[S4]

```python
# 调用形式示例。生产中必须通过现有 BaoStock 会话/超时/Governor；不要另开无管控采集器。
fields = (
    "date,code,open,high,low,close,preclose,volume,amount,"
    "adjustflag,turn,tradestatus,pctChg,peTTM,pbMRQ,psTTM,pcfNcfTTM,isST"
)
rs = bs.query_history_k_data_plus(
    "sh.600519", fields,
    start_date="2020-01-01", end_date="2026-08-31",
    frequency="d", adjustflag="3",  # 本任务原始、不复权序列
)
```

必须检查登录结果、查询结果和迭代结束后的 error_code；保留行数上限、超时、EOF 防护和失败 checkpoint。SDK 半途报错不能把之前取得的部分行标记 COMPLETE。单一会话串行请求，禁止共享全局 BaoStock socket 并发访问。

字段契约：

| 输入 | 目标 | 约束 |
|---|---|---|
| date、code、OHLC | security_id、trade_date、raw_OHLC | A 股、指数、基金、B 股身份必须先区分；原始执行价不使用复权值 |
| volume、amount | volume_shares、amount_cny | 固定本接口/品种/版本的单位证据；禁止复用另一接口的乘数 |
| tradestatus、isST | 交易状态和 ST 候选 | 缺失是 UNKNOWN，不是 false；不能从成交量为零直接推断停牌 |
| preclose | 原始参考昨收 | 不是可分离现金分红/送转的证据 |
| peTTM、pbMRQ、psTTM | 对应已有估值候选 | 只补缺口，不重抓已经正式发布的估值 |
| pcfNcfTTM | 保留原始 NCF 语义 | 禁止映射成已冻结的 PCF_OCF_TTM |

先用现有解析与单位契约核对，再落标准列。基础库既有 release 在读取边界已做的手→股、千元→元转换不得再次施加到新源已标准化的数据上。[S1]

**样本**：从实际研究池选沪市主板、深市 `000xxx`、深市 `002xxx`、创业板、科创板，再覆盖有 ST、停牌、除权、退市边界的真实事件窗口。事件样本来自证据，不假设任意示例证券一定具有相应事件。沪深 A 股任务明确排除 B 股；北交所独立取得资格后才能扩范围。

### A2. 备用价格：腾讯路径只做字段级资格，不自动替换

优先复用 QuantRadar 既有、已做样本资格检查的腾讯适配器。AKShare 调用形式为：[S5]

```python
ak.stock_zh_a_hist_tx(
    symbol="sz000001",
    start_date="20200101", end_date="20260831",
    adjust="", timeout=30,
)
```

审阅的源码已对量额做转换，输出包含 `date/open/close/high/low/volume/turnover/amount`；不能照搬旧文章再统一乘 100/10000。其单位转换对证券前缀有分支，必须将 `sz000001` 与沪深指数分开实测，不从“函数文档写股/元”推导所有品种已正确。

它内部有按年份循环，调用日期范围不一定等于请求范围。必须对“小范围补数”的实际请求列表做测试，不接受一次缺口请求悄悄重抓多年的情况。AKShare 腾讯与 a-stock-data 腾讯属于同一上游，不算两份独立证据；未验证字段保持缺失。换源只能在采集阶段生成新候选/新 release，不能在回测中发生。

### A3. 上市、退市、证券身份与交易日历

沿用已有 `bs.query_stock_basic()` 采集路径；单证券补漏可用 `bs.query_stock_basic(code="sh.600519")`。核验 `code/code_name/ipoDate/outDate/type/status` 等实际列，保留原始身份与采集时点。当前主数据可提供有效日期材料，但并不自动还原所有历史名称、代码变更和历史公开时点。[S1][S2]

```python
# 在既有登录会话中使用，返回值按 BaoStock ResultSet 契约收集。
rs_basic = bs.query_stock_basic(code="sh.600519")
```

以下是**本地 SDK 需追加资格检查的查询候选**，不是本文件已经完成真实历史验收的接口：

```python
bs.query_all_stock(day="2020-01-02")
bs.query_trade_dates(start_date="2020-01-01", end_date="2026-08-31")
```

先检查本地签名/返回列/指定历史日期是否生效，再启用；`query_all_stock` 的状态列命名可能与日线不同，不直接套用 daily parser。已有日历覆盖时不重抓。股票上市/退市日期只能构造“存续资格”，不能代替 ST、可交易状态或完整历史池审计。

深圳退市核验可用 `ak.stock_info_sz_delist(symbol="终止上市公司")`；沪市可查看 `ak.stock_info_sh_delist(symbol="全部")`，但返回字段中“暂停上市日期”等名义不能未经语义核验就当终止上市日。`ak.stock_zh_a_st_em()` 是当前 ST 清单，只作当下校验，不回填历史 ST。[S6]

### A4. 复权依据与真实股票公司行为

研究价格与执行价格分别保存。`adjclose`、复权因子与真实事件相互核查，但因子不代替现金/股份事件账。

`bs.query_adjust_factor(code="sh.600519", start_date="2020-01-01", end_date="2026-08-31")` 列为 SDK 待资格候选；本地确认函数、参数、因子锚定和除权样本后，才允许参与研究价格重建。不能据名称把某个 factor 直接乘在全历史所有列上，也不能把含派息调整的因子倒数直接用于成交量。

**股票真实分红送转的首选待验接口**：[S6]

```python
stock_events = ak.stock_dividend_cninfo(symbol="600519")
```

按实际返回字段保留实施公告、登记日、除权日、派息日、股份到账日、方案说明等。只有实施状态和计量基数已确认的记录可转账务事件。对文档列为“每 10 股”的派息/送股/转增：

```text
cash_per_share = 派息比例 / 10
bonus_shares_per_share = 送股比例 / 10
capitalized_shares_per_share = 转增比例 / 10
share_multiplier = 1 + bonus_shares_per_share + capitalized_shares_per_share
```

空值只有被实施方案明确证实“不送/不转/不派”时才能归零。不能通用 `fillna(0)`。报告期不等于实施日期。税费按引擎已审计规则版本处理，不按固定 20% 虚拟预扣来掩盖事件错误。

BaoStock `query_dividend_data(code="sh.600519", year="2020", yearType="operate")` 只列为可选交叉核查候选：本地签名、年份口径、返回字段与覆盖通过后再使用，不以它的存在承诺完整配股、合并、拆并股覆盖。配股/合并等首版不支持事件要单独报出；允许经真实公告核验的结构化证据导入，不允许模型凭价格缺口猜事件。

### A5. 历史市值：库存重解析优先；历史 PE 不能充当市值

第一步检查已有东财 payload 和基础原表。若有 `market_cap`/股本等字段，则 `REPARSE_RAW`，不再联网。若只有正式 PE/PB/PS/PCF 列，则不能宣布 #56 数据已齐。

第二步使用：

```python
cap_history = ak.stock_value_em(symbol="600519")
# 接口没有 start_date/end_date；返回其可取得历史后，本地按需求过滤。
```

文档字段包括数据日期、总市值、流通市值、总股本、流通股本等；总市值与流通市值分开保存，按当前文档及样本核验币种/单位。[S6]

已有东财日期切片适配器使用：

```text
GET https://datacenter-web.eastmoney.com/api/data/v1/get
reportName=RPT_VALUEANALYSIS_DET
columns=ALL
filter=(TRADE_DATE='2026-09-11')
sortColumns=SECURITY_CODE
sortTypes=1
pageNumber=1
pageSize=<既有限额>
source=WEB
client=WEB
```

只能复用现有 Adapter 的分页/唯一性/total 校验，先看实际响应字段，不凭字段猜测宣称市值完整。股票解析失败台账保持隔离；同一东财端点换成 requests 包装不是独立来源，也不构成自动放行资格。[S1]

第三步可选百度候选：

```python
ak.stock_zh_valuation_baidu(
    symbol="600519", indicator="总市值", period="全部",
)
```

文档只有 `date/value` 等，不足以在本任务里确认总市值单位。禁止自行固定“亿元乘 1e8”；先取得单位证据、对拍同日市值，并检查非交易日记录来源。未确认时标 `UNIT_UNVERIFIED`，不得作为 #56 正式输入。[S6]

历史总市值不能由今天股本乘过去股价、流通市值或估值比率倒推替代。

### A6. 多级行业：历史变迁与当前字典是两类数据

```python
history = ak.stock_industry_clf_hist_sw()
level1 = ak.sw_index_first_info()
level2 = ak.sw_index_second_info()
level3 = ak.sw_index_third_info()
```

- `stock_industry_clf_hist_sw()` 为全市场行业变迁材料。优先复用现有 `SwIndustryAdapter.history()` 保存的申万文件，不重复下载。[S6]
- `sw_index_first_info/second_info/third_info` 审阅实现来源是**乐咕乐股**，提供当前层级/名称等，不是历史行业公开版本库；三者访问同一页面，可在经过测试的 Adapter 中一次取回再解析三个表。[S7]
- 必须检查历史材料究竟含哪些层级。只看到一级历史，不能声称通过当前三级字典就补齐三级历史。
- 申万分类代码与行业指数代码不一定是同一个编码体系；不得只靠字符串截取、补零或当前行业名称连接。新增明确的版本化代码映射，缺失历史字典保留 UNKNOWN。
- `start_date` 是候选生效日期，`update_time` 是源侧更新时间；二者均不自动等于过去策略可获得数据的时间。

本任务沿用原方案的 82 项量价、1 项市值（#56）、18 项行业的分组，但实施须由公式解析/依赖矩阵核对；不能仅靠手写数量验收。未就绪行业项单独阻塞，不能锁死已合格量价项。

### A7. 历史指数成分：先复用历史库，当前快照只用于更新与核对

基础 `ts_index_weight` 已有材料优先审计：实际快照日期、完整性、调样生效、别名映射证据区间、临时调整与可用时间。不能继续无限延用旧快照。[S1]

```python
# 最新公布快照候选；没有历史 start/end 参数。
ak.index_stock_cons_csindex(symbol="000300")
ak.index_stock_cons_weight_csindex(symbol="000300")
```

a-stock-data 等价能力见 A8。上述来源的日期必须取源侧快照日期，不能改成采集日期，也不能复制成每日历史。[S2][S8]

可追加资格检查 `bs.query_hs300_stocks(date="2020-01-02")`、`bs.query_zz500_stocks(date="2020-01-02")`。明确区别“接口接受 date”与“该历史日真实完整成分已证实”：需要以多个真实历史调样窗口和公告进行交叉验证。不要编造未核验的中证1000同名接口。

无法取得完整指数历史时，可以另设“可审计存续 A 股池”的研究版本，但必须用户可见地变更实验定义，不能静默替换原指数池。固定当前股票池可做软件样本，不宣称无幸存者偏差。

### A8. a-stock-data 的具体用法与边界

以下为固定 `SKILL.md` 内嵌函数调用形式，并非可直接导入的 PyPI SDK；需要先按既有做法抽取、审阅和适配。此轮不再整体引入 60 个入口。[S2]

```python
baostock_valuation_history("600519", "2020-01-01", "2026-08-31")
baostock_stock_basic("600519")
history = sw_industry_history()
sw_industry_as_of(history, "600519", "2020-06-30")
index_constituents("000300", provider="csi")
index_weights("000300", provider="csi")
trading_calendar(2026, 9)
```

具体选择：

| 上游函数 | 本轮使用方式 | 限制 |
|---|---|---|
| baostock_valuation_history | 参考代码归一化与字段解析；调用归并到既有日线 bundle | 不为了同一 BaoStock 数据再请求一遍；不含所需历史市值 |
| baostock_stock_basic | 参考身份/上市退市解析 | 当前基本信息不等于全部历史代码变更 |
| sw_industry_history / as_of | 复用历史文件与基础 as-of 思路 | 最近有效行查询不等于严格 PIT 或完整三级历史 |
| index_constituents / weights | 保存官方最近快照、核验现有尾部 | 无历史任意日期回填能力 |
| trading_calendar | 补尚未覆盖月份的官方日历 | 不重复下载已经合格的基础日历 |

禁止运行时下载 SKILL 并 `exec` 全文件。按实际源记账，例如 `upstream=baostock`、`implementation=a-stock-data@<commit>`；AKShare/自写 requests/该 skill 调同一上游不算多源验证。不采用绕过访问控制、轮换 IP 或超限重试。

## G2：ETF 轮动的数据接口与用法

首批建议冻结 10—20 只境内权益 ETF 的名单与纳入规则。示例 `510300`、`510050` 仅用于接口说明，不是推荐购买或按回测收益筛选出的名单。黄金、跨境、债券、货币 ETF 在单独数据资格包中推进。

### E1. ETF 清单与身份：当前清单只做发现入口

```python
ak.fund_etf_category_sina(symbol="ETF基金")
ak.fund_etf_spot_em()
```

二者用于当前 ETF 代码/报价快照和候选发现，不是历史完整在市/退市名录。[S9]

ETF 必备身份：交易所、上市日、终止日、基金/份额类别、交易币种、跟踪指数、类别变化和规则生效日期。基金成立日不等于交易所上市日；最早行情日只说明所取价格覆盖，不是上市日期证明。

小池通过真实基金管理人或交易所的上市交易公告、终止公告、基金合同、实施公告补证。允许建立带证据文件 hash、页码/定位和核验者的结构化导入表。本文没有核实到一个可以直接提供上述全部历史字段的统一免费接口，不把当前列表或模型猜测当成替代。

### E2. 日行情主入口：东财 ETF；新浪用于已核验字段对拍

```python
prices = ak.fund_etf_hist_em(
    symbol="510300", period="daily",
    start_date="20200101", end_date="20260831", adjust="",
)
# 全可得历史型函数：不接受上述 start/end 参数，拉取后本地裁切。
check_prices = ak.fund_etf_hist_sina(symbol="sh510300")
```

东财日线包含 OHLC、成交量、成交额等；新浪 ETF 历史接口不提供本任务需要的完整成交额/权益事件，先只批准已验证价格字段。新浪没有成交额时保持缺失，不能用 close×volume 伪造。[S9]

**单位必须逐端点、品种和解析版本确认**：基金成交单位标准化为“份”和“元”，股票标准化为“股”和“元”。保留源值和转换因子；不能因为另一个接口以手记量，就对所有 ETF 一律乘 100。可用 amount/volume 与日内 low/high 做一致性检查，但这只是异常检测，不是单位证明。不同市场或历史阶段例外要单独限定覆盖。

`adjust="qfq"`、`adjust="hfq"` 仅作为研究价格/总回报口径的核对材料；前后复权返回价不是自动可用的总回报账户账本。日终信号在 t+1 执行，成交价用 raw OHLC。

### E3. 基金分红与拆分：年份必须显式传入，分页必须闭环

审阅的 AKShare 函数默认年份是 `2025`，不是“所有年份”。`page=-1` 会在函数内部取完整分页；`page=1` 只取第一页。[S10]

```python
# 首次资格样本：少量年份/页面，不在研究池每只ETF上重复调用。
ak.fund_fh_em(year="2020", typ="", rank="BZDM", sort="asc", page=1)
ak.fund_cf_em(year="2020", typ="", rank="FSRQ", sort="desc", page=1)

# SDK支持以下全分页形式，但生产需将限流、超时和证据保存落实到每一次内部请求：
# ak.fund_fh_em(year="2020", page=-1)
# ak.fund_cf_em(year="2020", page=-1)
```

生产请求契约：

```text
GET https://fund.eastmoney.com/Data/funddataIndex_Interface.aspx
分红：dt=8；拆分：dt=9
year=<明确年份>
page=<当前页>
rank=<已批准排序字段>
sort=asc 或 desc
gs=
ftype=
```

每年先取得分页元数据，再把每页作为 Governor 管控的独立请求保存 payload，核对页数/可取得总数/事件主键/排序稳定性；并发或源侧修订导致页间错位时保留失败，不用去重掩盖漏页。空年份须有“源确实无记录”的有效响应证据，HTTP/解析异常不能当零事件。

按所有必要年份完成采集后，再本地筛选首批 ETF 的准确基金/份额代码。首次全基金年份数据只取一次；已冻结旧年份不逐日重取，安排独立、有界的修订核查。新年份事件可按研究需求增量更新，不能仅抓除息日已经过去的事件而漏掉未来支付日。

字段映射：

| 端点字段 | 标准事件含义 | 禁止误用 |
|---|---|---|
| fund_fh_em：分红 | 文档为元/份，保存 cash_per_unit | 不能像股票“每10股”再除10 |
| 权益登记日/除息日期/分红发放日 | record_date/ex_date/pay_date | 三者不能合并成一个 date |
| fund_cf_em：拆分折算日/类型/拆分折算 | 待实施方案确认后的份额乘数/生效日 | 不对所有数值机械 +1；不要把联接基金或其他份额事件归入 ETF |

审阅实现用 `eval` 解析远端内容，且内部分页请求未接入 QuantRadar 的请求治理。不得照抄该解析方式：生产 Adapter 使用受限结构解析（满足格式时用 JSON；必要时经严格截取及大小限制后用 literal-only 解析），禁止执行响应中的任意表达式，解析失败原样留证。也不得全局 monkeypatch requests 影响其他数据链路。[S10]

### E4. 基金事件公告：作为证据入口，不能只信首页和摘要

```python
announcements = ak.fund_announcement_dividend_em(symbol="510300")
```

审阅源码取 `f10/JJGG` 的 `type=2` 公告列表，提供基金代码、公告标题、基金名称、公告日期、报告ID；当前实现固定 `pageIndex=1`、`pageSize=1000`，不是经完整性证明的全历史翻页器。[S11]

生产 Adapter 需检查元数据是否表明还有页面，必要时受控翻页；若无法证明列表完整，就如实记录证据覆盖边界。列表只是定位材料，派息金额、除息/到账、拆分换算仍需取得真实公告正文核验，不能拿标题或报告ID直接填账。

`ak.fund_etf_dividend_sina(symbol="sh510050")` 返回除息日期和累计分红一类数据，只能对拍累计口径，不能将“累计分红”当成本次现金派息，也不能独立补齐登记日/支付日。[S9]

### E5. 净值：注意参数是 fund，不是 symbol

```python
nav = ak.fund_etf_fund_info_em(
    fund="510300", start_date="20200101", end_date="20260831",
)
```

保留净值日期、单位净值、累计净值、日增长率等实际列；这类返回日期本身不提供历史实时可得时间证明。申购/赎回状态不是二级市场可交易状态。累计净值简单 pct_change 也不能不经方法核验就称“红利再投资总回报”。[S9]

价格型轮动不使用 NAV 时，只要其真实权益与账户收益已验收，不因 NAV 缺口全局阻塞。涉及折溢价、净值动量时，NAV 数值、时间和收益口径均为硬依赖。不能用事后公布的同日 NAV 计算较早时点信号；禁止仅机械延后一天便宣称所有品种已严格可得。

### E6. 交易规则、停牌、基准

本次已核实的接口没有证明能统一补齐所选 ETF 全历史的上市规则、涨跌停价格、份额变更和暂停交易。首批对每只 ETF 建立带生效区间与官方证据的规则记录：买卖单位、最小价位、回转限制、涨跌停机制、费用和特别交易状态。

不能把所有 ETF 设成相同 T+0/T+1、不能将所有基金套股票费率。涨跌停池不是全市场每日涨跌停价格表；当前 ST 清单不是历史交易状态。规则计算涨跌停价只有在证券类别、规则版本、适用期间和参考价等前置字段全部合格时开放，输出必须标明“规则推导”而不是“原始行情”。日频不能证明涨跌停触价时一定成交，执行规则采取明确、保守且可解释的假设。

基准只补实际用到的指数或组合序列，优先复用基础库；基金上市前不得用指数拼出可交易 ETF 净值。没有合格避险 ETF 时用显式零收益现金，货币 ETF 另行资格检查。

## G3：数据正确不等于策略可复现——共同计算与账户门禁

### G3.1 输入面板

标准价格量额→VWAP→收益率/ADV→Alpha 运算，不为可派生字段新增网络源。

- `VWAP=amount_cny/volume_shares_or_units` 只在量额同范围同口径且量大于零时可算；零量、缺量/额保持原因。
- 研究 OHLC/VWAP 调整一致；不能复权 close 搭 raw open/high/low。证券跨拆分的量价口径单独定义，不机械套总复权因子倒数。
- 价格复权锚定日期必须写入契约。对使用绝对价格/横截面排序的公式，加入“追加未来分红拆分不能改变当时可用输入”的防泄漏回归；不要直接把今天的前复权水平当作所有历史时点的严格 PIT 输入。无法满足的研究口径单独标明，不悄悄升级为严格 PIT。
- 原任务中的 `adv_amount_d` 与 `adv_volume_d` 两种实现口径保留，使用哪一种写入公式规范与 hash，不静默交换。
- rank 为横截面、ts_rank 为时序；窗口取整、并列、NaN、除零、零方差、停牌日计数等规范固定；不 bfill，不静默缩小候选池。
- t 日完整收盘数据形成的信号最早 t+1 执行；原任务列出的 delay-0 公式在采用该时点时注明适配版。

### G3.2 权益事件与账务

新正式运行不得把“昨收−除权参考昨收”当作现金分红，不能固定 share_multiplier=1 冒充送转处理。旧 release 按历史契约回放并保留近似标签；修复产生新代码/数据版本。

登记日持仓决定权益；除息日应收/股数调整、支付日现金到款、股份到账/可交易日分别处理。在引擎尚不支持某类时点或事件时，先暴露具体不支持能力，不能伪造“会计正确”。用总回报价格评价时不能又把同笔现金重复加到账户中。

因子 IC、分层、多空差值诊断与实际可交易账户分开验收；统计性空头不被描述成已支持 A 股融券实盘。评价窗口与样本外协议冻结，不能边补数据边按表现改 ETF 池。

### G3.3 依赖门禁

分开给出 `FORMULA_READY / EVALUATION_READY / EXECUTION_READY / STRICT_PIT_READY`；名称可映射现有状态，不为本文重复造系统。

- 可计算的 82 项量价因子不因市值/三级行业缺口阻塞。
- 事件账未验收不妨碍独立检查公式，但不能宣布对应账户收益正式可信。
- 历史池不完整时可做固定池工程验证，输出明确局限。
- 缺失/未知交易状态不能设成正常；未使用 NAV 不成为无关工作流门槛。

## G4：请求治理、来源证据、发布与验收

### G4.1 Governor 必须约束实际请求

接口级配置至少包含上游、端点、请求单位、并发、超时、重试、失败分类与修订复查策略。沿用已批准的源级限流，不在此虚构“官方安全每秒请求数”。SDK 内部有 N 次请求，就应记录并治理 N 次，而不是函数外 sleep 一下。

已确认要重点审查：基金年份分页、基金公告首页限制、腾讯年份循环、东财全历史单证券接口。原始请求幂等键采用源/端点/规范参数/解析单位版本，发布审计键与采集 scope journal 分开；新 release 指针变化不能触发同一数据重复下载。

401/403/429、连接失败、源端空数据、schema 漂移、证券不覆盖分别分类；遵循实际访问权限及 Retry-After，禁止代理/IP轮换绕过。`NoneType` 解析错误不能直接当全局限流。196 个已知失败不批量盲重试；单独健康检查不改变失败历史。东财股票估值失败不自动冻结或放行基金端点。

### G4.2 保留证据层级，不伪装原始响应

建议沿用或扩展现有字段：

```text
upstream_provider / access_library / endpoint / request_params
source_snapshot_date / effective_from / effective_to / available_at
fetched_at / adapter_version / unit_contract_version / raw_sha256
base_commit / supplement_commit / evidence_level / pit_grade
```

HTTP 响应原字节：`HTTP_RAW`；BaoStock ResultSet 序列化快照：`SDK_RESPONSE_SNAPSHOT`；只有 AKShare DataFrame 的序列化：`PARSED_SNAPSHOT`。后两者能保留取得的数值，但不能伪称保存了网络原始响应、所有响应元数据或历史公告版本。

历史公开时间未知就保持未知，不把今天 `fetched_at` 当过去可用时间，也不把有效日/净值日/报告期直接当 `available_at`。同一数值经过第三方库再导出不增加独立来源数量。

### G4.3 逐个数据集的实施顺序

| 批次 | 工作 | 放行证据 |
|---|---|---|
| 0 | 本地版本/签名/schema/缺口扫描 | 无网络即可形成两个真实 gap_plan 与源契约差异 |
| 1 | 重解析 BaoStock 既有响应；补逐日状态/必要价格；规范量额 | 零重复请求证据、异常样本、固定版本回放 |
| 2 | 股票实施事件、原始/研究价格一致性、82 项输入 | 分红送转真实样本、输入对拍、公式依赖矩阵 |
| 3 | ETF 身份证据＋原始日线 | 真实上市边界、单位契约、主辅源价格对拍 |
| 4 | ETF 按年分红拆分＋事件公告＋执行规则 | 分页完整、事件单位与日期、份额/现金对账；一个轮动回放 |
| 5 | 历史市值重解析/缺口获取 | #56 输入总市值口径通过，不重开全估值工程 |
| 6 | 申万历史层级/字典、指数历史缺口 | 哪些历史已证实、哪些仍 PARTIAL/UNKNOWN 明确列出 |

批次指交付顺序，不要求已合格的数据重新采集；NAV 在策略需要或与小池事件核验直接相关时并入批次4。行情接入与历史会计分别验收，不以一项接口失败全局停工。

### G4.4 验收清单

1. **接口验收**：本地版本、签名、请求数、响应 schema、单位、实际首末日期、样本品种、原始/解析证据层级、失败语义。签名检查通过必须标 `NOT_NETWORK_TESTED`，不能显示“接口健康”。
2. **覆盖验收**：精确依赖分母不变；合法不存在和未知分开；上市前日期不伪造，已退市股票不静默删除，缺口未通过时拒绝相应资格。
3. **计算验收**：101 项矩阵不删行；独立小样本对拍、嵌套预热边界、as-of 防泄漏、错单位注入；符合资格的组分别交付。
4. **账户验收**：真实派息、真实送转/拆分事件证据与现金/份额账一致；合成测试单列，不计真实覆盖；未成交原因、规则版本和费率可见。
5. **性能与复现**：相同 release 断网回测无外部调用、同结果 hash；缓存命中与旧版本重跑不重复下载，原发布单位不被修改。
6. **有限补数**：复跑同一个 gap_plan 不重复 transport；季度/年份全局文件不按证券重复；内部页/年请求数可审计。
7. **输出**：在既有数据状态页面展示两个研究包的输入就绪、统计评价、执行、PIT 四种资格，不重做布局；保留下载计数与正式可用覆盖的区别。

建议产物名称（映射到既有目录，不为名称而新造系统）：

```text
interface_contract_report.json
alpha101_gap_plan.json
etf_rotation_gap_plan.json
alpha101_dependency_matrix.csv
source_qualification/<endpoint>/<scope>/
corporate_action_reconciliation.json
etf_rotation_fixed_release_acceptance.json
publication_manifest.json
```

完成标准不是盈利、行数最多或“全绿”。最终必须准确告诉用户：可复现哪些公式/策略、可用历史起止、采用何种股票/ETF池、哪些字段/时期仍有局限。

## 给本地 Codex 的执行指令

严格按 G0→逐数据集实施→回放→发布执行。先读真实 schema 与当前模块，提交最小修改计划及第一批 gap_plan 后继续实现，不重新讨论全系统架构。示例代码仅说明上游调用契约，生产必须集成既有 Adapter/Governor，不在回测中直接 import 数据库 SDK 联网。

不要默认所有文档接口在本机可用；不能以单样本健康替代全窗口覆盖。发现接口变化时保存真实异常及响应证据，修复独立解析器并测试，禁止把失败改成空表成功。无法取得历史行业/成分/规则证据时标明具体阻塞范围，先交付不依赖该资料的已合格工作流。
