# DataHub V1 — user-approved contract (2026-09-09)

Goal: DATAHUB_REPRODUCIBLE_PIT_V1_PASS. User approved implementation without
another design permission gate. docs/ACTIVE_PHASE.md is the goal authority.

## Scope

Shanghai/Shenzhen A shares including historically delisted securities. Target
valuation history starts 2016; earlier coverage is optional and cannot delay V1.
Three datasets: daily PE_TTM/PB_MRQ/PS_TTM/PCF_NCF_TTM; SW level-one industry
history (original historical code, effective_from/effective_to); lifecycle
(list_date, delist_date, status). Expose existing turn/is_st/tradestatus. Comparing
bao_* and Baostock is same-source consistency, not independent truth validation.

/data/investment_data remains the upstream read-only base. Never insert new data
or local commits there. /data/quantradar_data is the supplemental Dolt database.
PostgreSQL remains for tasks/runs/status, not supplemental research observations.

a-stock-data is adapter reference, pinned by full Git commit, never a backtest
online dependency. Probe baostock_valuation_history, baostock_stock_basic, and
sw_industry_history on this host before bulk backfill. Preserve source,
fetch_time/fetched_at, raw result or response, SHA-256, adapter/version.

Each dataset records PIT_STATUS PASS/PARTIAL/UNVERIFIED. Separate effective date,
publication/available date when supplied, and fetched_at. Without evidence of
historical public availability mark PARTIAL. Never use today's delisted status
to exclude a security before its historical delisting date. Unknown publication
dates remain unknown, not fabricated from effective dates.

## Publication and reads

extract → raw/staging → normalize → audit → quality gate → identify base commit
and create supplemental commit → immutable release manifest → atomic current
release switch. The base commit is read from upstream, never manufactured by
writing the read-only base. Both commits existing does not mean publication.

Manifest fixes base and supplemental commits, schema/version, dataset versions,
source adapter/version and provenance. A run resolves one release at start and
actually queries both immutable commits throughout. Old snapshot replay uses
that same release; concurrent updates cannot change its data. Failure at any
stage leaves current unchanged and old published data usable.

Support backfill, incremental sync, idempotence, bounded retries, interrupted
run recovery, history revision detection, audits. Required missing values cause
explicit research failure; optional missing values produce PARTIAL and an
excluded-sample record. Coverage denominator specifies universe, interval and
fields, distinguishing legitimate null, not-yet-listed, source unsupported, and
fetch failure. Preserve negative valuation ratios; never silently replace sources
or fill absent values with zero.

## Operations and UI

Reuse current DataStatus component. Display dataset/source/start/latest/stock
coverage/missing/PIT_STATUS/current release/last success/last failure/reason/
conflict or anomaly count. Manual update in UI plus CLI status/backfill/sync/
audit/update. systemd timer attempts daily update at 20:00 Asia/Shanghai, with
bounded retries; timing is not a promise of upstream availability.

## Exclusions

No FactorLab, AI21/23/73, GPT factor factory, full Residual IC, historical market
cap, SW levels 2/3, Beijing stocks, ETFs/funds, minute/tick/trades/orders, ESG,
complete consensus, financial-statement PIT, margin/block trades/shareholders.

## Ordered gates and acceptance

0. Read-only base audit and three live source probes, actual coverage/limitations.
1. Minimal DataHub and the three datasets.
2. Backfill/sync/audit/release/fixed-version reads.
3. Existing UI, CLI and systemd.
4. Real acceptance evidence for all twelve criteria:
   1. Repeated same update: no duplicate data or changed result.
   2. Real backfill and incremental sync both run.
   3. Interrupt update; current release unchanged.
   4. Recover/re-run interrupted update.
   5. One supplemental source fails; old release remains usable.
   6. Required missing field fails corresponding research explicitly.
   7. Optional missing is PARTIAL with excluded samples.
   8. Changed published data generates new release manifest.
   9. After database update old release actually queries old commits.
   10. Old replay result hash equals original.
   11. Real research example reads base and supplemental new fields together;
       profitability is not an acceptance requirement.
   12. Browser shows actual status, gaps and update results.
