# DataHub V1 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for bounded
> independent implementation tasks and reviews, after Gate 0. Execute gates in
> order; user has already authorized execution, no further design approval.

**Goal:** Deliver DATAHUB_REPRODUCIBLE_PIT_V1_PASS with real immutable reads.
**Architecture:** Existing read-only provider plus a small supplemental reader;
Dolt version databases pin queries. An immutable JSON manifest and atomic local
current pointer publish the pair. Source results are stored by hash and every
update is bounded, journaled and guarded by a single process lock.
**Tech Stack:** Existing Python/pandas/pymysql/FastAPI/React; Dolt; stdlib
argparse/json/hashlib/fcntl/os.replace; Baostock and xlrd for verified sources.
**Spec:** docs/superpowers/specs/2026-09-09-datahub-v1.md

## Global constraints

- /data/investment_data is read-only, never add local commits or supplemental rows.
- /data/quantradar_data is the supplemental Dolt; PostgreSQL is application-only.
- Only SH/SZ A stocks, SW level 1, four valuation fields, lifecycle including delisted.
- PIT_STATUS is dataset-specific; historical availability unproven means PARTIAL.
- All run reads use the release's actual immutable commits, including universe,
  calendar, prices, extras and supplements. No latest fallback for an old release.
- Do not introduce FactorLab or any other excluded feature.
- Gate 0 must finish before ingestion implementation or bulk historical backfill.

## Gate 2: publication, version reads and reproducibility

Files: backend/quantradar/datahub/{release.py,reader.py,pipeline.py};
backend/quantradar/{config.py,bootstrap.py,audit.py,snapshot.py,backtest_run.py,
backtest.py,worker.py}; providers/investment_data/{connection.py,provider.py};
tests/unit/{test_datahub.py,test_datahub_release.py}; acceptance script.

Interfaces: resolve_release(release_id=None) loads immutable manifest and validates
hash/version. Pinned base connection uses investment_data/<commit>; supplemental
reader uses quantradar_data/<commit>. Manifest identity derives from data commits
and version contracts, not run timestamps. Each run and resumed worker persists
release_id before data reads. Cache keys include release_id.

- [ ] Red tests: failed source/quality/audit/commit/pointer replacement leaves old
  pointer readable; same observations retain release_id; changed data yields new.
- [ ] Create Dolt commit after audit; immutable manifest first, then fsync and atomic
  pointer replacement last. fcntl prevents concurrent updates; readers never
  access staging/working HEAD. Use shared release ID across base/supplement.
- [ ] Red tests: old run after newer release retains original connections/manifest;
  required missing raises, optional missing yields exclusions/PARTIAL; no future
  lifecycle filtering or automatic source fallbacks.
- [ ] Extend existing provider fields for turn and attach supplemental read methods;
  preserve read-only responsibility. Thread release through worker/backtest/snapshot
  and existing research entry points, including restored historical configuration.
- [ ] Live SQL test on two real Dolt commits proves old values remain queryable.
