# QuantRadar 开发入口

文件：`docs/00_开发入口.md`

## 一、项目是什么

QuantRadar 是基于 BulletTrade 代码基线继续开发的本地量化研究平台。

核心架构：

```text
QuantRadar
=
BulletTrade Core
+
InvestmentDataProvider
+
数据审计与Snapshot
+
实验管理
+
中文WebUI
+
Qlib高级研究
```

当前主平台为 Ubuntu。

当前项目路径：

```text
/data/Projects/a-stock-research/QuantRadar
```

真实历史数据位于：

```text
/data/investment_data
```

Qlib 是 QuantRadar 使用的研究依赖，不重新开发 Qlib 核心。

Windows/QMT 只属于未来实盘执行节点，不属于当前研究平台主线。

# 三、执行权限

只有：

```text
docs/ACTIVE_PHASE.md
```

中的任务拥有当前开发权限。

`07_阶段路线图.md` 描述未来路线，但不是当前任务。

禁止因为在路线图中看到后续功能就提前开发。

例如：

```text
ACTIVE_PHASE = InvestmentDataProvider
```

则不得同时开发：

```text
React
Qlib
ETF
实盘
QMT
Agent
```

# 四、核心工程原则

始终遵守以下规则。

## 1. BulletTrade 是核心

不得重新实现：

```text
BacktestEngine
Portfolio
Position
Order
Trade
Scheduler
Commission
Slippage
Dividend accounting
```

如果 BulletTrade 存在缺陷：

```text
先写回归测试
→ 证明缺陷
→ 最小修改
```

---

## 2. investment_data 是正式数据事实源

正式研究：

```text
/data/investment_data
```

是唯一 Source of Truth。

可以使用其他数据源进行对账。

禁止：

```text
investment_data失败
→ 自动切换JQData/Tushare/AkShare
```

数据不足必须显式：

```text
BLOCKED
```

---

## 3. ETF不能阻塞股票主线

允许：

```text
A股股票 = READY
ETF = BLOCKED
```

禁止：

```text
ETF数据不足
→ 停止整个QuantRadar开发
```

---

## 4. 正确性优先

优先级：

```text
数据正确
>
防未来函数
>
会计正确
>
可复现
>
性能
>
UI
```

---

## 5. 不伪造成功

禁止：

```python
except Exception:
    return []
```

掩盖问题。

禁止：

```text
缺停牌数据 → paused=False
缺公司行为 → 假设没有分红
缺factor → 使用adjclose冒充
```

必须明确能力状态。

---

# 五、任务结束规则

每次 ACTIVE_PHASE 完成后必须：

```text
1. 运行规定测试
2. 保存测试证据
3. 更新 docs/CURRENT_STATE.md
4. 标记完成项
5. 记录 BLOCKED
6. 记录残余风险
7. 提交 Git commit
8. 停止
```

不要自动进入下一 Phase。

下一阶段必须由：

```text
docs/ACTIVE_PHASE.md
```

重新指定。

---

# 六、Codex 输出格式

每次任务结束只需要报告：

```text
## 本次完成

## 修改文件

## 测试结果

## 证据

## Blocked

## 剩余风险

## 建议下一阶段
```

不得用大量文字重新解释整个系统。

---

# 七、最终判断标准

QuantRadar 的价值不是功能数量。

核心目标始终是：

```text
一份可信数据
→ 一个统一Provider
→ BulletTrade可靠回测
→ Snapshot
→ 可复现实验
→ Web工作台
→ Qlib高级研究
```

任何新增功能如果不能加强这条主线，暂不实施。
