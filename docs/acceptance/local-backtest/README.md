## 实际操作路径

1. 策略回测 → 载入样例 → 在 Monaco 中用键盘编辑源码 → 填写策略名 → 保存策略版本。
2. 切换到其他样例 → 打开已保存版本 → 刷新整个页面 → 再次打开同一版本。
   确认重新提交的源码与保存版本逐字一致，包含实际输入的注释。
3. 设置日期、资金、基准及复权 → 运行策略回测 → 等待 SUCCESS → 打开完整回测报告。
4. 查看聚宽风格原生收益报告 → 详细报告 → 实际展开 trades.csv 和 daily_positions.csv 表格
   → 查看日志 → 返回继续编辑。
5. 运行记录 → 选历史运行 → 恢复源码与配置。另先改变编辑草稿与资金，再恢复旧运行并重新提交：
   源码、日期、资金、频率、基准、复权、extras 与原运行逐字段一致，结果哈希也一致。
6. 从报告点击策略菜单，草稿仍在；依次访问数据状态、研报、实验对比、策略回测和运行记录，
   菜单内容切换，报告不再挡住目标页面。
7. 实际输入故意失败策略并提交，提交页和历史记录均显示 FAILED 与
   `browser_expected_failure`，不会出现成功报告入口。

## 首次失败与沿流程修复

基线 `40bd7e8e`：首页 → 策略回测 → 编辑源码 → **找不到保存入口**。
[首个阻断截图](01-before.png)；浏览器检查保存按钮数为 0。
编辑器初始 Loading 数秒后可用，并非永久失败。初始行情 500 来自本机 Dolt 未运行；
现有 investment_data 已以 127.0.0.1:3307 只读服务启动，没有更新行情。

已修复策略版本保存与重开、报告切换导致草稿丢失、报告阻挡菜单、历史源码/配置恢复、
标准报告失败仍算成功、原生初始资金取成首日收盘资产、原生指标单位错误、
加载策略重置复权设置、无限盈亏比不能落 PostgreSQL，以及缺基准数据却显示零收益。
Monaco 已本地打包，不再依赖编辑器 CDN。

再平衡曾在产生报告后因原生 Infinity 指标落库失败：
`run_a9e681d49e154f748ce72e71541e9f86`，见 [失败截图](rebalance-infinity-failure.png)。

验收改用本地已覆盖的 `600519.XSHG`，未补新数据或把缺失当零。

## 支持范围与限制

- 本地可信用户、单 FastAPI 进程、现有 PostgreSQL Worker、A 股日频；支持原始价和前复权。
  自定义源码内显式 get_price(fq=...)、set_benchmark/set_option 仍按原生策略语义覆盖相应设置。
- 本次验证的证券为 600519.XSHG、000001.XSHE、000002.XSHE，指数基准为 000300.XSHG；
  其他证券/区间仍取决于本地数据覆盖，不代表全市场或全日期保真认证。
- 不支持分钟回测、后复权撮合、实盘、多用户鉴权或完整聚宽 API 等价性。
  Qlib、Kronos、新数据源、ETF 及其他扩展不属于本轮。
- 策略保存为不可变源码版本，页面列出最近 100 个版本；历史配置跟随运行记录保存。
  未保存草稿在菜单和报告切换时保留，刷新浏览器前需保存源码；尚无草稿自动保存、版本删除或大规模策略库分页。
- 聚宽风格报告的图片内嵌；详细原生报告交互图仍引用 Plotly/ECharts CDN，
  完全断网下的交互图不在本次验收范围，源码编辑和本地回测不依赖这些 CDN。
- 研报每日运行配置未改动；本轮没有重新验收研报服务，工作区原有两处未提交研报改动被保留。
